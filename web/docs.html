REST API

Everything the web app does is also a plain REST API on the same server — you can script uploads, searches, queueing and reads with curl or any HTTP client. Base URL: http://<your-server>:8480 (or your HTTPS address behind a reverse proxy).

Authentication

Two ways to authenticate; every /api/… endpoint accepts both:

  • API token (recommended for scripts and agents): create one under Settings → API. Tokens look like bp_…, are shown once, and are stored hashed. Send them as a header: 
    Authorization: Bearer bp_YOUR_TOKEN
  • Session cookie: POST /api/auth/login returns a JWT and sets a session cookie (30 days) — what your browser already uses.

A token acts as you and sees exactly your shelf (your books plus anything shared with you). Treat tokens like passwords — revoke any you no longer use.

# list your books
curl -H "Authorization: Bearer bp_YOUR_TOKEN" \
  http://localhost:8480/api/books?q=dune

Responses are JSON. Errors come back as {"detail": "…"} with a matching HTTP status (401 unauthenticated, 403 not allowed, 404 not visible to you, 409 conflict).

Interactive reference

A live, try-it-out reference is generated from the server itself: /docs (Swagger UI — works signed-in from this browser) and the raw schema at /openapi.json.

More curl examples

# upload a book
curl -H "Authorization: Bearer bp_YOUR_TOKEN" \
  -F "file=@mybook.epub" http://localhost:8480/api/books

# search the store and queue the first result
curl -H "Authorization: Bearer bp_YOUR_TOKEN" \
  "http://localhost:8480/api/zlib/search?q=project+hail+mary"
curl -H "Authorization: Bearer bp_YOUR_TOKEN" -H "Content-Type: application/json" \
  -d '{"id":"<id from search>","name":"Project Hail Mary","authors":"Andy Weir"}' \
  http://localhost:8480/api/zlib/queue

# save reading position (same call the web reader makes)
curl -X PUT -H "Authorization: Bearer bp_YOUR_TOKEN" -H "Content-Type: application/json" \
  -d '{"cfi":"epubcfi(/6/14)","pct":42}' http://localhost:8480/api/books/11/progress

# send a book to your Kindle
curl -H "Authorization: Bearer bp_YOUR_TOKEN" -H "Content-Type: application/json" \
  -d '{"device_id":1}' http://localhost:8480/api/books/11/send-to-kindle

MCP server

Bookplate exposes an MCP (Model Context Protocol) server, so AI agents — Claude Desktop, Claude Code, Cursor and any MCP client — can search your shelf, organize collections, and queue downloads from the stores in natural language. The agent acts as you: it sees your shelf (your books + what's shared with you) and can do everything your account can.

1. Create an API token

Settings → API → give it a label like “Claude” → Create token. Copy the bp_… value immediately — it is shown once.

2. Connect your client

Endpoint: http://<your-server>:8480/mcp (streamable HTTP, authenticated with your token header).

Claude Code (terminal):

claude mcp add --transport http bookplate http://your-server:8480/mcp \
  --header "Authorization: Bearer bp_YOUR_TOKEN"

Claude Desktop, Cursor & other JSON-configured clients:

{
  "mcpServers": {
    "bookplate": {
      "type": "http",
      "url": "http://your-server:8480/mcp",
      "headers": { "Authorization": "Bearer bp_YOUR_TOKEN" }
    }
  }
}

Accessing your server over the internet? Use its HTTPS address in the URL — the token crosses the network on every call. Treat the token like a password: anyone holding it has your account.

OPDS catalog

Bookplate publishes your shelf as an OPDS 1.2 catalog — the standard way reader apps browse and download from a library. Point your iOS reader app at:

http://<your-server>:8480/opds

Sign in with your Bookplate username and password (HTTP Basic auth) — not an API token. You'll see every book you own plus books shared with you, with covers, descriptions and one-tap downloads.

Adding the catalog on iOS

  • KyBook 3 — Network → OPDS catalogs → + → enter the URL, your username and password.
  • MapleRead — Shelf → OPDS → + → enter the URL and credentials.
  • Yomu — Catalogs → + → OPDS → enter the URL and credentials.

Reading progress is not synced through OPDS — it's a download channel. Read in the Bookplate web reader (or download from it) to keep your position across devices.

Plain-HTTP caution. Basic auth sends your username and password cleartext on every request. On a trusted home LAN this is fine; for anything wider, put a TLS reverse proxy (e.g. Caddy) in front and use the https:// address in your reader app.

Send to Kindle

One click on any shelf card (⋯ menu → Send to Kindle) emails the book to your Kindle through Amazon's document gateway. Kindle accepts EPUB and PDF; other formats are converted where possible or rejected by Amazon.

One-time setup

  1. Register your device — Settings → Kindle devices → add a label and your Kindle's address (find it in Amazon → Manage Your Content and Devices → Preferences → Personal Document Settings; it ends in @kindle.com).
  2. Approve the sender — add the server's sender email to your Amazon account's Approved Personal Document E-mail List (same Preferences page). Admins see the configured sender address under Admin → App settings → Send to Kindle; otherwise ask your admin for it.

Not arriving? Check the approved-sender address matches exactly, look in your Kindle's Personal Documents library and your email spam folder, and make sure the book is EPUB or PDF. The server admin configures the SMTP gateway once, under Admin → App settings; sending stays disabled until then.

Self-hosting

Bookplate ships as a multi-arch Docker image (amd64 + arm64 — x86 servers, Apple Silicon, Raspberry Pi, ARM NAS). Everything lives in one volume, /app/data: the SQLite database, book files and covers. Backup = copy that volume.

# quick start
docker run -d --name bookplate -p 8480:8480 \
  -v bookplate-data:/app/data ghcr.io/bacnh85/bookplate:latest

# or with compose (recommended)
docker compose up -d
# then open http://localhost:8480

First boot

On an empty database the app creates the admin account itself: username from BOOKPLATE_ADMIN_USER (default admin); password from BOOKPLATE_ADMIN_PASS, or one is generated and printed once to the container log and saved to data/initial_admin_password — read it, sign in, then delete the file. After first login, configure everything in the UI under Admin → Settings (Z-Library, Anna's Archive, AI, SMTP, registration) — values live in the database; no provider env vars, no restarts.

Environment variables (all optional)

BOOKPLATE_DATA_DIRdata directory override (non-default volume mounts)

Backup, restore & migration

Stop the server, copy the volume (or the host data/ dir), done. Moving a local install into a named volume:

docker run --rm -v bookplate-data:/dest -v "$PWD/data":/src:ro alpine \
  sh -c 'cp -a /src/. /dest/ && chown -R 1000:1000 /dest'

The chown matters: the container runs as uid 1000 — without it the migrated database is unwritable and the container crash-loops. Binding a host directory instead of a named volume? Pre-create it with the right owner: mkdir -p data && sudo chown 1000:1000 data.

Security & operations

  • The server is plain HTTP — put a TLS reverse proxy (e.g. Caddy) in front for anything beyond a trusted LAN (OPDS and the reader apps use basic auth).
  • A healthcheck is built in; docker ps shows healthy once up.
  • Local development: python3 -m venv .venv && .venv/bin/pip install -r requirements.txt, then scripts/serve.sh (binds 127.0.0.1:8480; HOST=0.0.0.0 for LAN testing).

Admin guide

Admin-only screens live under Admin → Users / App settings / Z-Library.

Users & registration

Registration defaults to approval required: new signups land as pending, can't sign in, and wait in Admin → Users. There you can approve, enable/disable, change roles, and reset passwords. The last active admin can't be demoted or disabled. In App settings you can switch registration to closed.

App settings

  • Z-Library — account email + password and a mirror (pick a healthy domain with zlib doctor --eapi). All users share this one account and its daily download quota through a single FIFO queue that waits out exhausted limits and retries transient failures (3 attempts, 5/30 min backoff).
  • Anna's Archive — member secret key + mirror. Downloads work with or without a membership (members get the fast API path; free accounts automatically use the slow partner servers, waitlists included). If search starts failing with a bot check, open the mirror once in a normal browser on the server's network — the DDoS-Guard clearance is per-IP.
  • AI assist — enable, then set an API key for any OpenAI-compatible endpoint. Defaults expect z.ai: base URL https://api.z.ai/api/paas/v4, model glm-4.6. A wrong base URL shows up as “AI endpoint returned junk {404_NOT_FOUND}” for every request — that's a route problem, not a model problem.
  • Send to Kindle — the server-wide SMTP transport (host, port, STARTTLS/SSL, credentials) and the sender address users must approve in their Amazon account.
  • Registration — approval-required or closed.

Z-Library administration

The Z-Library tab shows the account's daily quota, its download history (one click re-queues any item) and the account's saved books (“My library”). Booklists are not exposed by z-lib's API and show as unavailable.

Secrets (store passwords, keys, SMTP password) are stored in the database and masked in the API — the “clear” link empties a field. Same on-disk trust boundary as the data volume itself: whoever can read /app/data can read them, so protect the volume.

FAQ & troubleshooting

I can't sign in

New accounts need admin approval (default registration mode) — you'll see “waiting for admin approval” after signing up. Disabled accounts are locked out everywhere. Ask an admin, or if this is your server, approve yourself under Admin → Users.

The download queue says the Z-Library limit is exhausted

All users share one account with a daily quota. The queue waits and re-checks automatically — jobs resume when the limit resets. Failed jobs retry on their own (3 attempts, 5/30 min backoff); you can also retry or cancel from the Downloads panel.

Uploading the same file twice

Re-uploads of an identical file dedup instantly (content-addressed storage by SHA-256). A logical duplicate — same normalized title + author, different file, e.g. two scans — is flagged after upload so you can compare and remove one.

Which formats can I upload?

PDF, EPUB, MOBI, AZW3, FB2 and CBZ. Everything gets automatic metadata, a guaranteed cover (embedded art → PDF page-1 → enrichment → generated placeholder), and full-text search. EPUB/MOBI/AZW3/FB2 read in the in-browser reader with synced progress; PDF and CBZ stream page-by-page.

Anna's Archive search suddenly fails

Usually the DDoS-Guard bot check: decisions are per-IP, so if your server's IP is flagged, complete the checkbox once in a normal browser on the same network. Mirrors also rotate — if the default dies, set a current mirror in Admin → App settings.

“AI endpoint returned junk {404_NOT_FOUND}”

The AI base URL is wrong (every request 404s, which looks like a model problem). Set it to https://api.z.ai/api/paas/v4 under Admin → App settings — not an /openai/v1-style path.

My reader app can't connect to OPDS

Checklist: the URL is http://<host>:8480/opds (no /api); you're using your username and password, not an API token; your account is approved; and — over the internet — the server is behind HTTPS, since some networks block plain-HTTP basic auth.

Kindle email never arrives

The sender address must be on your Amazon Approved Personal Document E-mail List, the book must be EPUB or PDF, and the SMTP gateway must be configured by the admin. Check the Kindle's Personal Documents library and your spam folder. See the Send to Kindle page.

Where do I manage API tokens?

Settings → API. Tokens are shown once at creation and stored hashed — if you lose one, create a new one and revoke the old. Anyone holding a token has your account.

How do I back everything up?

Everything lives in the one data volume (/app/data, or your local data/ dir): database, books, covers, settings. Copy it while the server is stopped. See Self-hosting.
